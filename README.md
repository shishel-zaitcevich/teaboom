# Teaboom — карточка товара (тестовое задание)

Верстка верхней части карточки товара интернет-магазина [Teaboom.ru](https://teaboom.ru/)
на примере товара [«Ананасовый улун»](https://teaboom.ru/product/ananasovij-ulun).

## Стек

- **Vite** — сборка, dev-сервер, бандлинг.
- **Vanilla JS (ES-модули)** — без фреймворков, компонентный подход.
- **SCSS** — модульно, отдельный файл стилей рядом с каждым компонентом.
- Без Bootstrap и готовых шаблонов

## Запуск проекта локально

```bash
# 1. Установить зависимости
npm install

# 2. Запустить dev-сервер (с hot reload)
npm run dev
# откроется на http://localhost:5173

# 3. Собрать production-версию
npm run build

# 4. Локально просмотреть production-сборку
npm run preview
```

## Структура проекта

```

├── src/
│   ├── main.js                    # инициализация приложения: берёт товар и рендерит ProductCard
│   ├── data/
│   │   ├── products.js            # моковые данные товара (форма ответа будущего API)
│   │   └── api.js                 # заготовка реального похода на бэкенд (drop-in замена products.js)
│   ├── components/                # каждый компонент — своя папка: разметка + логика + стили
│   │   ├── ProductCard/           # корневой компонент карточки, собирает остальные
│   │   ├── Gallery/                # изображение товара
│   │   ├── PackagingSelector/     # переключатель фасовки (100 г / 500 г / 1000 г / 5000 г)
│   │   ├── AddToCartButton/       # кнопка «В корзину» с hover/active-состояниями
│   │   └── Description/           # блок краткого описания
│   ├── styles/
│   │   ├── main.scss              # точка входа для глобальных стилей
│   │   ├── abstracts/             # SCSS-переменные и миксины (цвета, breakpoints, адаптив)
│   │   └── base/                  # reset, типографика, контейнер страницы
│   └── utils/                     # formatPrice, createElement — переиспользуемые хелперы

└── .env.example                   # пример переменной для будущего API
```

## Архитектурные решения

**Компонентный подход.** Каждый визуальный блок — самостоятельный модуль:
JS-функция, которая создаёт и возвращает DOM-элемент, плюс свой `.scss`-файл рядом
(импортируется прямо в JS-файле компонента, как в React/Vue-проектах). Компоненты
переиспользуемы и не завязаны на конкретный товар — весь контент приходит через
параметры.

**Данные — как будущий ответ бэкенда.** `src/data/products.js` хранит массив
товаров в формате, который логично ожидать от REST-API (`id`, `variants[]` с
`price`/`oldPrice`/`sku` и т.д.). Функция `getProductBySlug()` уже возвращает
`Promise`, как это делал бы настоящий `fetch`. Когда появится бэкенд — правится
один импорт в `main.js` (с `./data/products.js` на `./data/api.js`), сигнатура
и форма данных не меняются, поэтому компоненты трогать не нужно.
